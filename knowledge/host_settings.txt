The first complete manual overwrite then exposed the directory API mismatch:
after deleting only save.dat, XDeleteSaveGame failed because SaveMeta.xbx and
saveimage.xbx remained in the directory. Original recursive helper 309AA7 queries
326 bytes at 309ACF, consumes only FileName at +40, and queries again after each
deletion. It never follows NextEntryOffset. Xbox's ten-argument
NtQueryDirectoryFile always returns one entry; our native provider had packed
several into one response and advanced past all of them. Returning one entry
per request preserves the remaining entries for the original helper's loop.
Independent API behavior reference (ReturnSingleEntry=TRUE):
https://github.com/Cxbx-Reloaded/Cxbx-Reloaded/blob/master/src/core/kernel/exports/EmuKrnlNt.cpp
The original helper and native API evidence, not the observed error alone,
establish this fix. Burnout's overwrite-in-place path did not expose this case.
--trace-storage records cold storage requests explicitly; ordinary play and
F8's bounded recent-IO ring do not enable that verbose diagnostic.
