World 2 loading stop: incomplete primitive tails - 2026-10-28
Verified XBE SHA256: 9B49918BC4CD0D2541369534F9A458679F43C63462869F0F37C0ED69B3349DC2.
User report: build/logs/game-stopped-1793217468443.json. The boundary is
"Incomplete triangle list", at CDevice_KickOff (3207B0) while draining graphics

An incomplete primitive is legal: completed triangles render and the remaining
one or two vertices are discarded. Primary references:
https://registry.khronos.org/OpenGL/specs/gl/glspec15.pdf
  Primitive specification for triangles (3n+k vertices, final k ignored).
https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm
  Section8.13, Partially Completed Primitives. Lists/strips discard incomplete
  primitives, including a five-vertex triangle list producing one triangle.
NV097 implementation cross-check:
https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/gl/draw.c
  pgraph_gl_flush_draw forwards element/array counts to the graphics API without
  requiring a multiple of three. This is research, not a runtime dependency.

Fix: use D3D11's native incomplete-tail handling for line/triangle lists. For
converted loops, fans, polygons, quads and quad strips, emit only complete
primitives; an undersized primitive emits no geometry. Resource, index and
buffer bounds remain checked. No draw is replaced with a fabricated triangle.

four-vertex triangle-list variant reproduces the exact error before rebuilding

indexed/array triangle tails, line tails, quad tails, quad-strip tails, and
undersized converted primitives. Nineteen pixel comparisons have zero changes
