tools/Recover-Calls.ps1 provides the recovery loop:
  Plan     refresh Analysis and rank the complete queue.
  Prepare  select related families, preserve a baseline and inspect their code.
  Inspect  continue pending functions, or follow explicit -Entry addresses.
  Check    refresh Analysis and compare the result with the preserved baseline.
Use -Family to select exact queue IDs. Defer -Family ID -Reason TEXT records a
specific missing proof; Resume -Family ID returns it to the active queue.
Deferred sites remain counted. Failed checks retain the baseline for repair.

The queue assigns every unresolved instruction exactly once: exact global
slots, indexed tables, observed receiver candidates, then local owners. Method
offsets alone do not combine object types. Preparation batches shared producers
and consumers, joining original bytes, writes, address uses, constructors,
existing pointer-source contracts and known callers. The packet states the
remaining proof obligations. Indexed callers/writes and observations are leads,
not exhaustive writer/alias proofs. It never writes proof facts automatically.

Private queue, packet, baseline and check reports are under
build/logs/call-workflow/. Audit the packet, add proven shared facts to
knowledge/static_calls.json or improve general recovery, then run Check.

reserve All and runtime checks for runtime changes or milestone validation.
