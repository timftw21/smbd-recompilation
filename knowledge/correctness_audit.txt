Source correctness audit of 2026-11-24
=====================================

Revision 92618e2264d69b89498e1916fb968baf3adc0557, US retail XBE v1.
All 77 tracked files under src were in scope, including platform-specific code,
headers, embedded HLSL and both assembly implementations. The inventory below
accounts for 37 C++ files, 38 headers and two assembly files, 26,941 lines.
The numbered findings describe that revision. Repair verification follows
finding 16. The November 1 research follows separately.

The first repair priorities were the clean Linux build and event delivery. One
prevented a fresh build on a standard Linux filesystem. The other could strand
a waiting game thread. The performance and macOS requirements have separate
results below. Each source reference is relative to the audited revision.

Findings
--------

1. High. Fresh source preparation fails on a case-sensitive Linux filesystem.
   src/pipeline.cpp:30,42,60 and Build.sh:58. The disc spells its root entry
   Default.xbe. Preparation writes that spelling and immediately opens
   default.xbe. On Ubuntu ext4, verify-disc passed, prepare exited 1 with
   "Cannot open .../default.xbe", and verify succeeded on the extracted
   Default.xbe. The bounded fixture retained the original directory spelling,
   sector and all 7,143,424 executable bytes. Its only file was the XBE, so the
   check exercised the actual extraction path without rescanning all media.
   Write and verify one canonical host filename for the supported executable.
   Keep the spelling from the disc in its metadata. The packaged installer
   already selects the lowercase destination at src/installation.cpp:81.

2. High. Two event signals can collapse into one while threads are waiting.
   src/xbox.cpp:1003,1015,2713,2739,2916. Take two threads already waiting on
   one auto-reset event and a third that calls SetEvent twice before yielding.
   Both calls store 1. Only when a waiter runs does it consume that bit. One
   thread can remain asleep indefinitely. A waiting thread can also miss a
   notification event set and cleared during a single turn. The scheduler
   needs to commit eligible waits at signal time, including consumption and
   multiple-object wait results. A released thread may execute later.
   This follows from the signal and wait paths. The gameplay run did not hang.
   The XBE imports NtSetEvent at 003475F0 and KeSetEvent at 0034767C. Microsoft
   specifies one satisfied wait per synchronization-event signal. ReactOS
   independently shows wait-list processing in its dispatcher implementation.
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-kesetevent
   https://github.com/reactos/reactos/blob/master/ntoskrnl/ke/eventobj.c

3. Medium. Xbox window clipping is lost for multiple or exclusive rectangles.
   src/gpu.cpp:46 and src/render.cpp:2292. The verified 768-byte Xbox routine
   D3DDevice_SetScissors at 0031E760 has a fast path for a single inclusive
   rectangle. Its other path programs a full-surface clip at 0031E934, clip
   type at 0031E949 and the separate horizontal/vertical window registers.
   The native draw state reads only 0200/0204 and submits one D3D11 rectangle.
   A probe of the actual gpu_render_state function returned (0,0)-(640,480)
   for the full surface, two disjoint inclusive windows, and the same windows
   in exclusive mode. Pixels outside the requested mask can be drawn.
   Implement the window mask in addition to the surface
   clip and cover inclusive and exclusive overlap. This is a draw-state
   discrepancy. The first-level recording does not identify an affected shot.
   https://github.com/abaire/nxdk_pgraph_tests/blob/main/src/tests/window_clip_tests.cpp
   https://raw.githubusercontent.com/XboxDev/nxdk/master/lib/pbkit/nv_regs.h

4. Medium. Frame replay can display the wrong render target.
   src/gpu.cpp:380,870 and src/frame_replay.cpp:200,223,294. The live flip
   resolves the currently selected surface. Its capture end record omits the
   surface ID. Replay infers it from the last draw or clear. For example, after
   rendering to a secondary buffer, a game can rebind the display buffer and
   flip without another draw. Replay then copies the secondary buffer. A final
   surface write or blit also leaves this inferred target unchanged. Record
   the presented surface at flip and use that ID during full replay. The
   inspected 362-draw recording happened to reproduce exactly.

5. Medium. A full frame comparison can report success with a different image.
   src/frame_replay.cpp:295,307 and src/tool.cpp:207. A complete 640x480 frame
   replayed all 362 draws with zero differing RGB pixels and exit 0. Repeating
   the same default command with one reference pixel changed at (10,10)
   reported one differing pixel, passed=true and exit 0. The draw records,
   payloads and original reference stayed intact. Only D3D diagnostics feed
   the verdict. Marking the original trace footer and manifest truncated in
   a separate copy also returned passed=true and exit 0 with all 362 draws.
   Expose an image-verification verdict and failure exit for full replay, with
   an explicit tolerance. Partial draws and enhancement comparisons can keep
   reporting their differences. The existing tolerance-based comparator at
   src/render.cpp:384 has no caller in either native executable.

6. Medium. Metadata-only opens conflict with ordinary saves on Linux.
   src/host_posix.cpp:84 and src/xbox.cpp:1824. On a writable ext4 file, an
   exclusive data reader followed by FILE_READ_ATTRIBUTES | SYNCHRONIZE with
   zero share returned error 32. Reversing the order produced the same error.
   The same two sequences both succeeded against native CreateFileW on NTFS.
   The Linux loop lets the metadata-only handle participate in reciprocal
   data-sharing checks. Exclude it on both sides of that check. The existing
   metadata-sharing cases at src/xbox.cpp:3071 use the read-only disc provider.
   https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew

7. Medium. File queries return last-write time in the change-time field.
   src/xbox.cpp:2078,2318,2365 and src/host_posix.cpp:169. Both handle and
   pathname queries place LastWriteTime in the fourth timestamp slot. A guest
   can set a different ChangeTime and get success, then receive the wrong
   value on its next query. Linux even persists an explicit change time as
   user.smbd.change_time, but both read paths omit it. This establishes a
   mismatch between the provider's setter and getters. FATX directory entries
   have three stored timestamps. Establish the retail driver's ChangeTime
   policy before choosing a persistent fourth value or an explicit alias.
   The XBE imports NtQueryFullAttributesFile, NtQueryInformationFile and
   NtSetInformationFile at 003475D4, 00347560 and 0034755C.
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_basic_information
   https://aerosoul94.github.io/blog/2020/02/25/fatx-reading-and-recovery.html

8. Medium. Writable-file queries lose preallocation and pending deletion.
   src/xbox.cpp:2072,2083,2098,2299,2309,2368. For an empty save, reserve
   65,536 bytes with FileAllocationInformation and then query its allocation.
   The native setter reserves storage while retaining EOF zero. Every query
   derives allocation from rounded EOF, so the guest gets zero. Standard
   information also leaves DeletePending zero after successful disposition
   changes. Query the maintained allocation and disposition on both platforms,
   respecting the Xbox allocation unit. The distinction matters to programs
   checking whether they reserved space or requested successful deletion.
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_standard_information

9. Medium. A save opened write-through can complete a buffered write.
   src/xbox.cpp:1822,2096 and src/host_posix.cpp:108. Writable creation records
   option 0x2 for FileModeInformation, but generates host flags only for
   directory access, overlapped I/O and delete-on-close. The requested
   durability is lost on both hosts. The Linux provider already implements
   FILE_FLAG_WRITE_THROUGH using O_SYNC if it receives the flag. Forward the
   option when opening the file and honor it on every completion path.
   The title imports NtCreateFile at 00347580. This is a service-contract
   finding. Loss of an actual player's save was not observed.
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile

10. Medium. A translated integer divide fault reports the wrong guest address.
    src/cpu.h:432,441,444,448 and src/recompiler.cpp:1744. With the original
    routine at 0030BBD0, six divided by three returned EAX=2. One divided by
    zero exited the probe with code 3 and EIP=0030BBD0. The faulting original
    instruction is F7 F1 (DIV ECX) at 0030BC1B. The helper throws an ordinary
    C++ exception before committing guest state or recording the instruction.
    x86 specifies divide-error vector 0 for a zero divisor or a quotient that
    cannot fit. Preserve the precise pre-fault state and expose the guest
    vector and address to exception handling and diagnostics.
    https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html

11. Medium. A recoverable thread error terminates guest execution on Linux.
    src/xbox.cpp:2601,2643 and src/host_posix.cpp:291. At suspend count 127,
    NtSuspendThread returns 0xC000004A. The original Xbox SuspendThread wrapper
    calls that service at 0030963A and branches to XapiSetLastNTError on error.
    At 00309225 the latter calls the imported RtlNtStatusToDosError. Native
    Windows returned 156 (ERROR_SIGNAL_REFUSED). The current Linux provider
    threw "NTSTATUS has no verified DOS error mapping" for the same value.
    Supply the verified mapping so the original wrapper can return failure
    and store the last error without ending the guest run.
    https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-

12. Medium. An update can lose track of obsolete installation files.
    src/installer.cpp:334,344 and src/installer_linux.cpp:409,419. Each updater
    publishes a pending manifest, installs the new manifest, then deletes files
    that the new version no longer ships. Both ignore deletion errors and
    report success. If an old file cannot be removed, the final manifest omits
    it, so the next update and uninstall have no record of the leftover file.
    Keep the pending manifest until cleanup succeeds and surface a file error
    that permits retry. The source paths establish this outcome. No installed
    game was upgraded or removed during this audit.

13. Low. Linux crash reporting calls a function outside the signal-safe set.
    src/diagnostics_posix.cpp:51,73. A fatal signal interrupts arbitrary code,
    then the handler formats JSON with snprintf before writing or re-raising
    the signal. POSIX does not guarantee that formatting call is safe there.
    It can prevent the original fault record from reaching disk. Format the
    bounded integer fields in a fixed buffer with signal-safe operations and
    keep the existing write loop. This result comes from the handler contract.
    https://man7.org/linux/man-pages/man7/signal-safety.7.html

14. Low. Linux setup leaves a file descriptor open when chmod fails.
    src/installer_linux.cpp:304,310. In the menu-entry writer, an fchmod error
    short-circuits the expression before close. The exception path unlinks
    the temporary file while setup still owns its open descriptor. Every retry
    can retain another descriptor until the process exits. Close it on both
    paths and preserve the original error for the message.

15. Medium. Full replay rejects frames that have no geometry draws.
    src/frame_replay.cpp:223,293. Clearing a screen and flipping is sufficient
    to display a frame. A complete 16x16 capture with one full red color clear,
    a surface and a matching reference exited 1 with "No captured draws
    selected". Replay processed the clear and then rejected it because the draw
    count was zero. Validate a completed frame independently of draw count.

16. Low. A live game report always claims the main dispatcher was not reached.
    src/main.cpp:443,607, src/xbox.cpp:741,2956 and src/boot.cpp:25. The game
    supplies dispatcher address 00014B90 and runs with an unlimited budget.
    That disables checkpoint diagnostics on its threads, yet the JSON copies
    the unobserved watch flag into main_reached. The completed Story run
    reported false and zero checkpoints after 3,080 frames and 926,595 draws.
    Record the first dispatcher entry once or report the field as unmeasured
    when the watch is disabled. Either keeps the gameplay hot path lightweight.

Repair verification
-------------------

The fixes use the same US executable as the audit. The original findings,
addresses, pre-fix results and historical timings below are retained so the
before and after results can be compared.

1. A fresh preparation on Ubuntu ext4 produced default.xbe from the disc's
   Default.xbe directory entry. Its 7,143,424 bytes matched the supported
   SHA-256. The index retained Default.xbe and sector 265. A second prepare
   reused the file. Both commands exited 0 on the bounded XDVDFS fixture.
2. The service diagnostic starts two real waiting fibers, signals before
   resuming either, and resumes them in reverse order. It checks two
   synchronization-event releases, notification set followed by clear,
   the winning wait-any index, consumption by a completed wait-all, and
   releasing two semaphore counts. The wait result is recorded while the
   dispatcher changes the signal state.
3. Native D3D11 checks read all 64 pixels of an 8 by 8 render for disjoint
   and overlapping inclusive and exclusive windows. Additive blending detects
   a double draw in the overlap. A packet check also verifies that writing a
   lower window register replaces the higher slots on the same axis. The XBE
   at 0031E9B1 and 0031E9FA subtracts one from each maximum before packing it.
   The renderer intersects the windows with the surface clip.
   https://github.com/abaire/nxdk_pgraph_tests/blob/main/src/tests/window_clip_tests.cpp
   https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/pgraph.c
4. A live capture recorded presented surface 3 on frame 186. Its 68-draw
   Windows replay matched every RGB pixel. A separate 60-draw capture on
   Linux also replayed exactly on its own renderer. A two-target control cleared
   the second surface last and presented the first. Final-blit and surface-write
   controls also matched. Legacy recordings lack the presented surface ID.
   Replay reports it as null when it must infer the target.
5. The audit's 362-draw frame passed with zero differing pixels. Changing one
   RGB channel by one at (10,10) failed full replay with exit 3, then passed
   with --tolerance 1. A truncated footer, truncated manifest and missing footer
   each failed. An isolated draw still reported its image difference. The
   standalone compare-images command also returned 3 on the changed reference.
6. Both open orders for a writable file are covered by the same guest calls.
   An exclusive data handle and a metadata-only handle coexist on NTFS and ext4.
7. FATX stores one update time. ReactOS's FATX driver accepts the last-write
   field on set and returns its value in both the last-write and change-time
   slots for basic and network information. The native services now implement
   that rule on both hosts. The check sends conflicting timestamps, then a
   change-time-only request, and compares both handle queries with the pathname
   query. In the XBE, 00304F0C clears the 40-byte request, 00304F12 calls
   KeQuerySystemTime on its last-write field, and 00304F25 submits class 4
   with the fourth timestamp still zero. The alias is supported by independent
   FATX implementation evidence. Direct retail-kernel confirmation remains open.
   https://github.com/reactos/reactos/blob/master/drivers/filesystems/vfatfs/finfo.c
   https://github.com/XboxDev/fatx/blob/master/libfatx/fatx_internal.h
8. The native service check reserves 65,536 bytes in an empty file. Query
   classes 5, 19 and 34 and the pathname query report the reservation. EOF
   stays zero when the reservation shrinks to 16,384 bytes and then to zero.
   Setting and clearing disposition changes the standard query's DeletePending
   byte. Writable allocations use 16 KiB guest units.
9. The diagnostic inspects the native mode of both a synchronous and an
   asynchronous guest write-through handle. Windows uses FileModeInformation.
   Linux reads the O_SYNC bits from the open descriptor.
10. The original unsigned division in 0030BBD0 still returns 2 for 6 / 3.
    For 1 / 0 its trap reports vector 0 and fault and resume address 0030BC1B.
    With a signed quotient one above INT32_MAX, original IDIV ESI at 00075D93
    also reports vector 0 at that instruction. EDX:EAX retains
    FFFFFFFF:80000000 and ESI remains FFFFFFFF.
11. Calling imported ordinal 301 with C000004A returns DOS error 156. This
    matches the Windows reference recorded for the original suspend wrapper.
12. Both updaters call the same finalization code. The previous and current
    filenames stay in the published manifest until obsolete file removal
    succeeds. Windows setup returned 1 for a locked obsolete file. The native
    finalizer was also exercised with a lock after the pending manifest was
    published. Linux setup returned 1 when an obsolete path was a nonempty
    directory. Each retry exited 0, retired the old name and preserved an
    unrelated sibling file.
13. The POSIX fatal handler writes bounded decimal and hexadecimal fields
    directly. An isolated Linux SIGABRT produced a complete crash record with
    signal 6, the native thread and instruction address, guest EIP 00014B90
    and flags 00000246. The original signal terminated the process with 134.
14. Linux setup closes the menu-entry descriptor on every chmod outcome and
    reports the saved error if cleanup also sets errno. An injected EPERM on
    the real desktop-entry write produced exit 1 and the expected permission
    error. Inspection before process exit found zero open menu-entry
    descriptors. A subsequent normal install created the desktop entry.
15. The original 16 by 16 clear-only capture now exits 0 with zero draws and
    zero different pixels. The final-blit and surface-write controls also
    complete without a geometry draw.
16. The one-checkpoint startup probe reports main_reached=false. A fresh,
    muted Windows Story run completed 27 controller steps and four waits in
    3,081 frames. It reported true with zero diagnostic checkpoints.
    A hidden Linux run also reached the dispatcher with zero checkpoints.
    Observation is attached to translated entry 00014B90.

Platform and performance requirements
-------------------------------------

The native macOS game cannot currently be built. CMakeLists.txt:447 rejects
a native batch outside Windows and Linux. The helper ABI in src/cpu.h:22
selects the x64 register convention only on Linux outside Windows. The current
helpers use x87/SSE, and src/floating.h:6 and src/frame_step.h:2 require x86
intrinsics. DESIGN.txt:88 requires a Mach-O helper path for Intel and direct
C++ helpers for Apple Silicon with a native Metal presentation path. README.md
already identifies macOS as planned. Physical Mac, Steam Deck, Linux GPU and
controller hardware, physical audio playback, and complete game progression
remain outside the observed coverage.

Windows benchmark host was an AMD Ryzen 5 5600X and a GeForce RTX 5060 Ti.
Both baseline rows used native 1x resolution, widescreen, 360 Hz selected,
VSync/AA/AF off, and movie/HUD upscaling and extended render distance off.
Each sampled 1,200 original rule ticks, approximately 20 seconds in one run,
with zero frame records dropped or mode/ball-state changes. Frame and GPU
entries are median / 99th percentile in milliseconds. CPU-side work uses the
recorder's wall time after pacing, scheduler and diagnostics are subtracted.
Peak memory is the process working set during the measured window.

Scene                    Frames    Frame ms       CPU work ms    GPU ms       Peak MiB

Night-Sky Rocket Lane     3,223    5.916 /10.554  5.869 /10.458  1.574 / 2.613   298.23

Every measured baseline interval exceeded the 2.778 ms target. PRO SKATERS
averaged 236 fresh frames/s and Bowling 161. A second Bowling run inherited
the local enhancement switches and measured 5.578 / 10.403 ms over 3,429
intervals. The two baseline processes took 48.8 and 47.4 seconds respectively
including startup, controller navigation, warmup, measurement and output.
Average translated guest-code wall time was 2.60 ms/frame on PRO SKATERS
and 4.05 ms/frame on Bowling. The GPU spans measured by the recorder stayed
below budget at p99 in both baseline scenes.

One Practice attempt using the current save ended in Bowling before the first
Practice barrier, exit 3. Its timing was excluded. The qualifying rerun used a
private copy of the project's PRO SKATERS benchmark save and verified mode 51,

Corrections

1. Pending I/O could signal freed/reused guest objects (high priority).
   queue_io retained a host OpenFile but kept only unreferenced guest file/event
   addresses. NtClose could recycle those slots before dispatch_io wrote their
   completion signals. Pending requests now retain both guest objects and release
   them after completion. File-handle waits now retain the enclosing FILE_OBJECT
   when waiting on its event at +0x38. Immediate asynchronous failures and empty
   requests also restore the file completion signal instead of leaving it reset.
   The new check-services command uses real asynchronous reads from the verified
   XISO, closes both handles before collecting completion, allocates another
   object, checks original XBE bytes and event signals, and checks final release.
   It uses isolated output storage and does not boot the game or open audio.
   Contracts: Xbox kernel NtReadFile ordinal 219, NtClose 187, NtOpenFile 202;
   native Xbox FILE_OBJECT packing and existing original SDK callers.
   Sources:
   https://raw.githubusercontent.com/XboxDev/nxdk/master/lib/xboxkrnl/xboxkrnl.h
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntreadfile
   https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-obdereferenceobject

2. Optimized sprite search changed a defined CPU flag (low priority).
   The original 00073900 exits a successful search after CMP tag,needle. The
   replacement used logic_flags, which retains AF, while an equal CMP clears it.
   The successful path now uses sub_flags for the original equal comparison.
   The existing CPU diagnostic exercises this with every arithmetic flag set.
   Evidence: build/logs/correctness-audit-sprite-original.json; the complete
   original routine signature remains checked by the lowering code.

3. Controller rumble stopped after an invented one-second timeout (medium).
   Original XInputSetState at 00342317 sends motor state without a duration.
   Input::rumble supplied 1000 ms to SDL and never renewed it. The input provider
   now keeps the requested motor state, renews before SDL expiration, clears it
   on disconnect and honors an explicit zero-motor command. The virtual-device
   input diagnostic checks persistence beyond one second and explicit stopping.
   SDL also handles device-specific hardware refresh; duration zero would disable
   that resend in the pinned SDL implementation, so it is not used as a shortcut.
   Sources (the SDL revision matches CMakeLists.txt):
   https://raw.githubusercontent.com/libsdl-org/SDL/829a65d769d935c4852f8159e964312c0957260a/src/joystick/SDL_joystick.c
   https://raw.githubusercontent.com/libsdl-org/SDL/829a65d769d935c4852f8159e964312c0957260a/include/SDL3/SDL_gamepad.h

4. Cubemap mip chains ignored Xbox face alignment (medium).
   GPU range calculation and native upload treated six faces as tightly packed.
   Each Xbox face starts on a 128-byte boundary, including its whole mip chain.
   Both paths now account for that spacing. The texture-cache diagnostic draws
   all six faces at each of two mip levels, with distinct padding bytes so a
   wrong face offset cannot accidentally pass. No claim is made that this format
   was the cause of an observed title scene defect; this fixes the supported
   renderer's cubemap data contract.
   Sources:
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/nv2a_regs.h
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/pgraph/vk/texture.c

5. Replay rejected resources below the capture writer's limit (medium).
   Captures permit 128 MiB of binary data, while replay rejected cumulative
   resource reads above 64 MiB. The reader now uses the writer's 128 MiB total
   limit and retains its separate 64 MiB per-resource bound. It still streams
   records and enforces resource, draw and stream limits.

6. Disc filenames could become Windows drive-relative output paths (high).
   Disc::directory rejected separators and dot components but accepted colons.
   A name such as C:escape.txt is a Windows path/stream expression, not a safe
   extraction component. Colons are now rejected when directory nodes are read,
   before extraction joins a filename to its output directory. A small synthetic
   XISO directory reproduces acceptance by the old tool and rejection after the
   fix; it does not contain game media. The supported disc remains accepted.
   Source:
   https://learn.microsoft.com/en-us/cpp/standard-library/path-class

7. Texture border addressing silently used black instead of the guest color
   (medium). Border addressing was supported, but NV097's per-stage border-color
   method at 1B24 + stage*40 was absent from RenderState and the native sampler.
   The bridge now carries that color into D3D11 and includes it in the pipeline
   cache key. The texture diagnostic checks two distinct colors outside the
   image, including a color change on an otherwise identical sampler.
   Source:
   https://raw.githubusercontent.com/xemu-project/xemu/master/hw/xbox/nv2a/pgraph/gl/texture.c

8. Querying an aliased allocation indexed outside its page metadata (high).
   NtQueryVirtualMemory used allocation(), which normalizes native guest RAM
   aliases, then subtracted the physical allocation base from the unnormalized
   query address. A valid 80000000/F0000000 alias therefore produced an enormous
   page index. It now uses the physical offset for metadata lookup and preserves
   the requested alias in returned region addresses. check-services exercises an
   interior address in the same allocation through all three supported mappings.

Static-analysis safeguard

The analyzer flagged a possible oversized shift in register-preservation proofs
(value_preserved, decoder.cpp). Both preservation helpers now reject register
indices outside the eight guest general registers before using a bit mask. The
existing recovery callers already try to establish that invariant; this check
makes it local and prevents undefined behavior if an invalid index reaches them.
It is recorded separately from the eight behavior defects above.

Additional findings

1. REP MOVS overlap was decided from guest virtual addresses. Two distant guest
   aliases can refer to the same overlapping RAM. The helper incorrectly selected
   memmove in that case, preserving a snapshot instead of reading earlier writes
   as the original repeated instruction does. It now compares resolved backing
   addresses, retaining element order for forward and reverse harmful overlaps.
   Original _memmove 30D820 compares guest pointers at 30D834/30D838 and takes
   the REP MOVSD path at 30D853 for the aliased case. Its complete bounded CFG
   contains 231 instructions. Before the fix, the native CPU probe of that actual
   routine copied successive input words through the alias; the expected result
   repeats its first word after each overlapping write. The new diagnostic also
   checks the returned guest address, three alias pairs and reverse copying.

2. Append-only writes were treated as ordinary positioned writes. The service
   sought using an offset that append-only handles must ignore and calculated
   the reported ending position from that ignored offset. Such handles also do
   not need a seek operation to append. Both synchronous and asynchronous writes
   now resolve append-only requests to EOF, leave native appending to the native
   handle, and report the resulting synchronous position. Diagnostics append
   actual XISO-derived header bytes with a supplied zero offset and inspect the
   resulting prefix, suffix, size, status and guest file-object position.
   Original SDK write call 30424E uses NtWriteFile IAT 347558 (ordinal 236).

3. File-opening paths kept GENERIC_READ/WRITE/EXECUTE/ALL request bits rather
   than expanding them to file-specific rights. Among other consequences, a
   GENERIC_ALL request bypassed the disc's read-only access mask and access
   queries returned unresolved generic bits. The same file-rights mapping is
   required before disc validation and native file creation. This also keeps
   sharing checks and append-only detection based on concrete access rights.
   Execute-only opens also bypassed read-sharing restrictions. Read sharing now
   accounts for both data and execution access, with the corresponding packed
   FILE_OBJECT access/share bits kept consistent. The data-read service still
   requires FILE_READ_DATA; execution access does not grant direct data reads.
   Metadata-only opens are excluded from data-sharing restrictions in both
   directions, and publish no data/share access bits. The full-access native
   diagnostic compares against a direct Windows open instead of assuming this
   account can obtain ownership-changing rights on the host file.
