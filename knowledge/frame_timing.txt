Status: this records the earlier repeated-image implementation. The user
explicitly rejected that implementation on 2026-10-28. Its acceptance results
do not establish true high-refresh rendering or high-refresh motion. See
true_refresh.txt for the subsequent native scene-step implementation and its
separate motion and gameplay validation. Results below are historical only.

Original evidence (bounded native analysis, build/logs/timing-*.json):

14D80 initializes the application and enters the shared loop at 14F00.
Its update calls include the movie service E6050, input 23F590/23ECC0,
state/pause handling 23FB50, resource work 16E30 and mode dispatch 15A90.
15BDF dispatches through mode table 476F78 using the mode at 6C9364.
The scene state at 6C9288 is independently established in first_level_automation.txt.

The same loop invokes object queues at 14FEA/1501F (1FD80), registered
callbacks through 168B0, HUD/effects through 6A1E0, and ends through 66E40.
It increments 6C9278 at 15110/15113 and unpaused counter 6C92D0 at 1511B.
6A1E0 consumes the queued draw count at 7196E8 via 6A2AE/6A2B6 and resets
it to zero at 6A2BE. This is queue consumption, not an effect lifetime.
Running these original paths once per host presentation changes game state.

66E40 calls 2A640, the common frame completion wrapper. Loading/save flows
also call the same wrapper (23320 -> 6FF00 and 23EEC0 -> 23F280).
The initialization/utility wrapper 2A720 also tail-calls it at 2A7D7;
2A73F sets interval 6DD788 to 1, for which the original counter spin exits
without waiting. A presentation limit alone therefore cannot fix game speed.
2A640 calls the original D3D Swap at 320190, checks the original vertical
blank counter through 36380, services E5990, toggles buffer index 6DD550
and increments frame counter 6DD54C at 2A670/2A677. 36380 installs callback
36370 through 31D940 and returns counter 6E88C8. The native video service
already uses a 60 Hz wall clock independently of game presentations.

Implementation:

Keep all original update, draw, queue/lifetime, movie, input and audio-service
ordering. Replace the original display-counter spin at 2A647/2A65B with a
cooperative wait until the next absolute 60 Hz deadline. Both instruction
signatures (E834BD0000 / 72EA) and the branch target are checked during AOT
lowering. Preserve the original counter call, arithmetic, callbacks, buffer
index and frame count. Simply waiting at Swap still leaves the original spin
active and can lose updates when a display deadline crosses a vertical blank.
The wait suspends only its guest fiber. Other guest threads, asynchronous I/O,
timers, video callbacks and SDL's 48 kHz audio stream continue independently.
Carry fractional nanoseconds and retain overdue steps. Mode/scene transitions
start a new epoch so time spent loading does not accelerate the next scene.
E5990 reads movie pointer 756080 and sync flag 756088, then tail-calls
the original D3D BlockUntilVerticalBlank (31D960) when both are active.
That service already waits on the independent 60 Hz video clock. Let it
own pacing for those movie frames, preserving its real wait and SDK effects
without stacking another wait first. E5990's initial TEST also overwrites
the incoming comparison flags; the original final buffer/index stores and
return ABI remain intact.

Presentation has its own clock and selectable cap, including Unlimited.
Capped displays run between guest slices; Unlimited uses producer idle time,
giving ready simulation work priority over repeated displays. Original update
steps, completed source images and
accepted native presentations are measured separately; startup/utility swaps
need not have a one-to-one relationship with original update steps.
The swap chain uses Burnout 2's one-frame DXGI latency queue and its waitable
frame-availability handle. Gameplay checks availability without blocking;
explicit diagnostics can wait. V-sync off also uses the supported flip-model
tearing flags, avoiding compositor refresh throttling. A GPU draw event alone
does not bound pending presentations, so the queue is managed through DXGI.
It never advances the guest, repeats draw callbacks, modifies assets or rescales
guest timestamps. One GPU-only color image retains the complete Swap result.
Presentation cannot sample in-progress targets, consume effect queues, blend
successive images or overwrite a target that the game will sample. It restores
the active target/viewport and uses nonblocking Present while playing so a
30 Hz cap or V-sync cannot suspend a 60 Hz guest update. Source and display
counts are reported separately; performance recordings identify the fixed
60 Hz source budget and the selected display budget separately.

This preserves the original 60 Hz motion cadence. It does not synthesize
additional motion samples or claim new scene renders on repeated displays.
All asset types use the same complete-image path; no per-asset rate guesses
or texture-frame patches are needed. Existing unresolved original calls and
unverified game-mode/visual parity remain separate from this timing change.

Resident memory uses actual color/depth sizes (RGBA8/D24: 4 bytes each;
RGB565/D16: 2 bytes each), counting a shared color image once. Shared-image
growth and retirement transfer that accounting correctly. CPU readback images
are allocated locally only when diagnostics request them. Keeping an unused
readback image for every live target, and counting shared colors repeatedly,
exhausted the former conservative accounting at 4x during the title/menu flow.
The completed-image buffer now fits within the same 256 MiB target budget.

Vertex/index uploads append into their existing bounded buffers, using
NO_OVERWRITE for untouched bytes and DISCARD only when wrapping. Previously
each draw discarded the full 8 MiB vertex allocation and index allocation,
forcing driver renaming stalls that made uncapped first-stage updates late.
The same approach is used by the Burnout 2 renderer. Constant-buffer uploads
retain their original handling; indices and stream offsets address only the
new region, preserving all earlier draws until the GPU finishes them.
