Texture format research - 2026-10-25
XBE SHA256: 9B49918BC4CD0D2541369534F9A458679F43C63462869F0F37C0ED69B3349DC2

The LLVM game probe game-0003 reaches NV097 texture format 04 during startup,
after the scene update callbacks. It stops before uploading that texture.

Format 04 is swizzled A4R4G4B4: two bytes per texel, with B in bits 0..3,
G in 4..7, R in 8..11 and A in 12..15. Microsoft's corresponding native
format is DXGI_FORMAT_B4G4R4A4_UNORM. The existing two-byte Morton unswizzle
can preserve its packed channel data, including mips, cube faces and volumes.
An actual GPU upload/draw is still required to validate the implementation.

XTPL inventory (metadata-only streaming read)
Original loader 0x00025580 checks XTPL magic 4C505458, reads count at +4,
and copies count 16-byte records from +8. Texture creation at 0x00021200
reads each record's resource offset at +4, then passes resource fields
+0/+4/+8/+C as format/width/height/mip count to 0x0032E4E6.

All 962 media TPL files use XTPL. Reading only these tables and 32-byte
resource headers produced 18,712 texture records, with no invalid or skipped
files: 05=52, 06=816, 0C=14,884, 0E=1,728, 1A=1,232. Container record tags
are not texture formats; resource headers supply the actual D3D format.
The private reproducible inventory is build/logs/texture-format-inventory.json.

1A is swizzled A8L8 (luminance in byte 0, alpha in byte 1). Sampling must
return L,L,L,A. Expansion to BGRA8 during the existing unswizzle preserves
these channels for every shader and requires accounting for twice the
source byte count in the native texture budget. A8L8 support is implemented
and the native build passed; runtime use of 1A has not been independently
captured. Runtime-created formats remain separate.

Texture allocation lifetime - 2026-10-28
XBE SHA256: 9B49918BC4CD0D2541369534F9A458679F43C63462869F0F37C0ED69B3349DC2
User capture: build/captures/frame-1793204422077-94783192500, frame 13885,
World 1 stage 1-19 HOLLOW. The displayed background contains unrelated grayscale
texture data, with additional corruption reported on trees and the monkey.

The captured guest texture bytes are intact. Replaying the same 410 draws with
fresh uploads restores the background and trees, changing 69620 RGB pixels.
The affected textures start at their own native guest allocation bases. For
example, the two views at 02B01000 both refer to a 45056-byte allocation containing
43680 bytes of texture data; the same holds at 02B0C000. The old bridge cached
uploads by address and descriptor indefinitely, without retiring the cached views
when the allocation was freed. Later levels reused these addresses for new data.

Native allocation release now invalidates overlapping texture and surface views
before their storage can be reused. Partial system-memory releases and virtual
decommits invalidate only the retired range. Pending uses are submitted first.
The renderer releases the native resources, returns their resident-byte budgets
and recycles the vacant slots. This requires no per-frame texture hashing or
changes to translated CPU stores. In-place edits without an allocation release
are a separate update path; this capture establishes allocation-reuse corruption.

Captures reserve unique resource IDs until the captured frame finishes, record
retirement events and retain retiring surface images. Offline replay separates
color allocations whose previous lifetime has ended. Capture manifests include
upload/eviction counts and the number of live texture-cache entries.

Validation on NVIDIA GeForce RTX 5060 Ti:
- check-texture-cache passes 64 unload/reload cycles with correct sampled pixels
  and stable GPU slots and resident bytes. It also checks overlapping address
  aliases, multiple texture views, shared-color/depth retirement and capture IDs.
- A hidden, muted 2202-frame game run retires 136 texture views and two auxiliary
  targets, leaving 142 live texture-cache entries after 278 uploads. Its final
  270-draw capture matches a fresh replay exactly, with no D3D11 debug errors.
- The earlier geometry capture still replays with zero changed RGB pixels.
- Native image-copy diagnostics pass; the 3-worker Game workflow passes with the
  unresolved-call count unchanged at 170.
Artifacts: build/checks/texture-reuse/current-textures, native-capture and
native-replay. Reports: build/logs/texture-cache-check.json and
build/logs/texture-reuse-validation.json. These checks do not establish complete
