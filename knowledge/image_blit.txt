Burnout's GPU bridge also rejects non-3D object operations, so it supplies no

The required copy must use the source's native GPU color contents. Copying its
original guest RAM allocation would lose rendered pixels. The destination must
remain sampleable as an updated GPU image. Flush queued draws, preserve command
order, validate format, pitches and rectangle bounds, and retain explicit stops
for unsupported operations. Investigate color-image identity if a copied image
is later bound as a render target; do not introduce separate stale color copies.
Renderer::copy_target currently copies the entire current target to another
same-size target. It lacks arbitrary source/rectangle support. Renderer targets
already have D3D11 texture, render-target and shader-resource views. Existing
Gpu::texture resolves matching GPU-produced render targets before RAM uploads.

Implemented and verified, 2026-10-25:
The earlier diagnostic has been replaced by native linear source-copy handling.
It flushes submitted draws, validates bound surfaces/format/pitches/rectangles,
and copies live native GPU color images with D3D11 CopySubresourceRegion.
New destinations define complete rows from the origin; existing native images
support rectangular and overlapping copies. Nonresident sources, unsupported
operations/formats and incomplete initial destinations retain explicit errors.
No stale framebuffer RAM is substituted for native rendered content.

Color images can be shared by render targets with different depth attachments.
Growth preserves shared color identity and each attachment's prior depth bits.
Linear GPU-produced texture coordinates receive the same normalization as
ordinary linear textures. Repeated copies reuse the destination image.
